# Спецификация ИИ-агента ИОТ

## Назначение

ИИ-агент формирует индивидуальную образовательную траекторию государственного гражданского служащего на основе профиля, должности, ИОГВ, истории обучения, официального каталога программ 2025 года и статистики коллег.

## Контракт входных данных

Профиль служащего:

```json
{
  "fio": "Иванов Алексей Петрович",
  "position": "Главный специалист",
  "department": "Администрация Губернатора Санкт-Петербурга",
  "experience_years": 3,
  "career_goal": "Развитие управленческих и цифровых компетенций",
  "learning_history": [
    {
      "course_name": "Название программы",
      "course_type": "ППК",
      "status": "Пройден"
    }
  ]
}
```

Поддерживаемые загрузки: `.json`, `.xlsx`, `.xls`, `.csv`, `.zip`.

## Правила рекомендаций

1. Курсы со статусом `Пройден`, `passed`, `успешно` или `done` исключаются из кандидатов.
2. Кандидатами является весь доступный каталог программ после исключения пройденных курсов.
3. Бенчмарк строится сначала по точной паре `должность + ИОГВ`.
4. Когортный бенчмарк отключен, пока владелец данных не задаст `MIN_COHORT_SIZE`.
5. После настройки порога, если точная когорта мала или отсутствует, система может использовать точный общегородской срез по той же должности и обязана показать limitation. Сопоставление «смежных» должностей по подстроке запрещено.
6. Если LLM-конвейер не завершился, fallback-результат маркируется как требующий экспертной проверки.
7. Матрица компетенций показывается только при наличии данных от модели/контракта; фиктивные уровни не создаются.

## Роли агентов

1. `competency-analyst` выделяет только подтвержденные профилем, историей и когортой сигналы развития; отсутствие измерений не превращается в «дефицит».
2. `trajectory-architect` выбирает кандидатов из полного каталога; структура этапов допустима только при обосновании входными данными, а fallback не назначает сроки.
3. `trajectory-justifier` формирует методическое обоснование и указывает ограничения источников; когортные данные используются только при наличии подходящего среза.

## Безопасность

Для внешних моделей ФИО заменяется псевдонимом `ГГС_ID_{hash}`. Локальная модель Qwen обрабатывает данные внутри закрытого контура. Ключи провайдеров задаются через `.env` и не должны попадать в репозиторий.

Платформа может работать без подключённой нейросети: аккаунты, каталог, аналитика, настройки и история доступны, а создание новых ИОТ возвращает `MODEL_UNAVAILABLE`. Проверенный опциональный локальный профиль: `Qwen3-1.7B-Q4_K_M.gguf`, context 4096, threads 4, batch 512, parallel 1. При `ENABLE_LOCAL_QWEN=true` deploy обязан сверить SHA-256 файла до запуска. Порт llama.cpp не публикуется на хосте; к модели обращается только `ai-driver` во внутренней Docker-сети.

Задача хранится в PostgreSQL и проходит состояния `Queued`, `Processing`, `Retrying`, `Completed`, `CompletedWithLimitations` или `Failed`. После каждого профиля сохраняется checkpoint. Процент в интерфейсе отражает только серверную стадию и не симулируется таймером. `CompletedWithLimitations` является резервным результатом: он требует экспертной проверки и не экспортируется как финальная ИОТ.

## Выходной контракт

Каждая рекомендация должна содержать:

- `course_id`, `course_name`, `type`, `duration_hours`;
- `annotation`, `learning_outcomes`, `competencies`;
- `justification`;
- `evidence_sources`;
- `cohort_evidence`, если курс найден в бенчмарке коллег;
- `limitations`, если источник неполный или fallback расширил правила.
