1. Что требует кейс
Цель — формировать для государственного гражданского служащего (ГГС) индивидуальную траекторию обучения ППК и ЭК по его должности, ИОГВ и истории обучения. Рекомендации должны опираться на опыт коллег с аналогичными должностью и ИОГВ, а уже пройденные программы не должны попадать в маршрут.

Данные и рекомендации
Профиль ГГС, история ППК/ЭК и каталог; индивидуальная траектория с названиями и краткими описаниями программ.
Маршрут учитывает профиль, историю и опыт аналогичных коллег; выстроен последовательно; у каждого курса есть конкретное обоснование.
Три группы агентов
Отдельные варианты на российских, зарубежных и локальных моделях; запуск локально или на сервере.

3. Блокирующие доработки P0
P0 — условия, без которых нельзя проводить защиту, показывать демо или заявлять выполнение базовых требований кейса.
P0-01. Frontend не запускается из-за отсутствующего импорта AccessibilityToolbar.
Проблема
Frontend не запускается из-за отсутствующего импорта AccessibilityToolbar.
Подтверждение
Lint указывает react(jsx-no-undef), а browser smoke-test зафиксировал ReferenceError в App.jsx. Компонент вызывается, но не импортируется.
Решение
Добавить корректный import из components/AccessibilityToolbar; добавить runtime smoke-test в CI, который открывает корневой маршрут и проверяет отсутствие console error.
Приёмка
Vite dev и production-сборка открывают стартовый экран; console errors уровня error отсутствуют; доступна форма построения ИОТ.
P0-02. ai-driver не стартует: в type annotation используется Optional без импорта.
Проблема
ai-driver не стартует: в type annotation используется Optional без импорта.
Подтверждение
agent_manager.py импортирует только Dict, Any, List; аннотация _pick_fallback_course содержит Optional. Изолированный import модуля завершается NameError.
Решение
Импортировать Optional; добавить тест импорта main:app и контейнерный healthcheck, который проверяет /docs или /agents/catalog после старта.
Приёмка
python -c 'import main' проходит в образе; ai-driver отвечает 200 на /agents/catalog; docker compose ps показывает healthy.
P0-03. Стандартное развертывание включает offline-демо вместо реальной системы.
Проблема
Стандартное развертывание включает offline-демо вместо реальной системы.
Подтверждение
env_example.txt и оба deploy-скрипта задают VITE_OFFLINE_MODE=true. В api.js offline-ветка создаёт локальные токены и task_id без обращения к backend.
Решение
Поставить false по умолчанию. Demo оставить только явным профилем с заметной маркировкой, отдельными тестовыми данными и запретом на защитный сценарий.
Приёмка
Новая установка без изменений .env обращается к backend. При недоступном backend отображается ошибка, а не «сформированная» траектория.
P0-04. Контракт загрузки не соответствует кейсу и не формирует предсказуемый набор данных.
Проблема
Контракт загрузки не соответствует кейсу и не формирует предсказуемый набор данных.
Подтверждение
JSON передаётся в ветку CSV-парсера; папки не поддерживаются как сущность; после загрузки нескольких файлов ProcessAnalysisAsync выбирает только первого пользователя. ValidationService унаследован от кейса опросов и проверяет «полезность/практичность» вместо полей ИОТ.
Решение
Разделить History / Catalog / Profile; описать JSON Schema и заголовки Excel/CSV; реализовать импорт папки/ZIP, выбор конкретного профиля или batch-режим. Удалить проверку анкеты и ввести валидацию ИОТ.
Приёмка
Позитивные и негативные тесты проходят для JSON, XLSX, CSV и ZIP-папки. Набор из нескольких пользователей либо даёт маршрут каждому, либо требует явного выбора пользователя.
P0-05. Рекомендации не выполняют ключевое правило «аналогичная должность и ИОГВ» и ограничены частью каталога.
Проблема
Рекомендации не выполняют ключевое правило «аналогичная должность и ИОГВ» и ограничены частью каталога.
Подтверждение
Бенчмарк индексирован только по должности; department не участвует в _find_position_benchmark. Агенту передаётся только первые 40 доступных курсов из 221. Fallback подставляет общие этапы, радар и шаблонные обоснования.
Решение
Сформировать бенчмарк по паре должность+ИОГВ с правилами для малых групп. Ранжировать весь каталог детерминированной функцией; не выдумывать данные при недостатке фактов.
Приёмка
На контрольном профиле выбранные курсы не пройдены, оправданы фактической статистикой соответствующей пары «должность+ИОГВ», а все 221 курса доступны кандидату.
P0-06. Обязательные выгрузки и повторяемый запуск не подтверждены.
Проблема
Обязательные выгрузки и повторяемый запуск не подтверждены.
Подтверждение
exportReportToJson обращается к необъявленным a и url; псевдонимы DOCX/CSV фактически вызывают PDF/Excel. deploy scripts выполняют docker compose down -v и стирают БД. Название Qwen 3.5 не совпадает с загружаемым Qwen 2.5.
Решение
Исправить JSON blob/download; убрать ложные форматы или реализовать их отдельно. Обычный запуск не должен удалять данные; закрепить точную модель, имя файла, хеш и версию.
Приёмка
JSON валиден, XLSX открывается и содержит маршрут. Два штатных перезапуска сохраняют историю. Версия локальной модели подтверждена в логе и документации.

5. Что делает разработка — порядок работ
Работы следует вести по зависимостям. Нельзя начинать с дизайна презентации или тонкой настройки промпта, пока не работает базовый запуск и нет достоверной выборки кандидатов.
Стабилизировать запуск: P0-01, P0-02, убрать offline по умолчанию, исправить deploy без -v, привести нейминг и secrets к кейсу 3.
Пересобрать контракты данных: отдельные схемы Profile, LearningHistory, CourseCatalog, ImportResult и Trajectory; поддержать JSON/XLSX/CSV/ZIP; добавить ясные ошибки валидации.
Реализовать прозрачный recommender: фильтр пройденных курсов, выбор когорты «должность+ИОГВ», правила малой выборки, ранжирование всех 221 курсов, evidence для каждого курса.
Подключить три группы агентов к одному контракту: строгий JSON Schema, retry для невалидного ответа, модель/версия в ответе и отключение фабрикации fallback-значений.
Исправить UI и выгрузки: интерактивный roadmap, экран источников/обоснований, JSON/XLSX, обязательный browser smoke-test, проверка доступности.
Добавить тесты: import/startup, parser, ranking, исключение «Пройден», outputs, model comparison, Docker one-command deployment.
