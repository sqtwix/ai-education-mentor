# Production hardening audit: перенос мер из похожего проекта

Дата основной проверки: 26 августа 2026 года. Режим штатного запуска без AI повторно проверен 30–31 августа 2026 года. Универсальный локальный provider (`local_llm`, managed GGUF/external OpenAI-compatible) проверен 31 августа 2026 года; упоминания Qwen ниже описывают конкретный исторический runtime, а не ограничение архитектуры.

## Граница переноса

`ai-education-mentor` остаётся продуктом для формирования индивидуальных траекторий обучения. Его основной поток не менялся: профиль сотрудника и история обучения → официальный каталог → проверенная ИОТ → аналитика реестра по должностям и программам.

Из похожего проекта переносились только общие меры безопасности, надёжности, проверяемости AI-результата, UX-состояний и production-инфраструктуры. Анализ анкет, sentiment, тематики отзывов, статистика опросов и другие чужие бизнес-сущности не переносились.

## Сопоставление всех десяти пунктов handoff

### 1. Frontend: production-поведение и API

Статус: уже было реализовано и повторно проверено.

- Production UI использует реальные API; offline-режим включается только явным `VITE_OFFLINE_MODE=true`.
- Авторизация, восстановление сессии, защищённые маршруты, архив, настройки, переименование и очистка устаревшего состояния уже работают через backend.
- Терминология и навигация сохранены в предметной области ИОТ.

### 2. Upload, validation и состояния

Статус: усилено в этом рефакторинге.

- Добавлены согласованные клиентские и серверные пределы: 25 МБ на файл, 50 МБ на запрос, 20 файлов.
- Для ZIP/XLSX проверяются число entries, распакованный объём и степень сжатия до извлечения; вложенные ZIP и неподдерживаемые расширения отклоняются.
- Временная директория гарантированно очищается и при исключении.
- Имя файла нормализуется и ограничено; пустые файлы отклоняются.
- Повторный `requestId` считается идемпотентным только при совпадении нормализованного payload профилей. Другое содержимое возвращает conflict.
- UI показывает пользователю форматы и фактические лимиты до отправки.

### 3. UI/UX и accessibility

Статус: системный UI-рефакторинг уже присутствовал; выполнена регрессия без смены продукта.

- Сохранены конструктор ИОТ, каталог, история траекторий, аналитика обучения и настройки.
- Unified dropdown, responsive layout, keyboard focus, loading/empty/error/disabled states и настройки доступности уже унифицированы.
- Проверка в браузере на 390×844: `scrollWidth == innerWidth`, горизонтального overflow нет.
- Экран аналитики показывает реальные должности, программы, охват и успешность обучения; он не превращён в анализ опросов.

### 4. Отчёт и экспорт

Статус: уже реализовано в объёме текущего продукта.

- View model строится из реального контракта ИОТ и не создаёт фиктивную competency radar.
- PDF/XLSX/JSON остаются поддерживаемыми форматами продукта.
- Результат `CompletedWithLimitations` нельзя экспортировать до экспертной проверки.
- DOCX/CSV из похожего проекта не добавлялись: они не являются подтверждённым требованием текущего продукта.

### 5. Реальный прогресс

Статус: исправлено в этом рефакторинге.

- Удалены условные 10%/30% из API и UI.
- При отсутствии серверного процента UI показывает indeterminate-индикатор, а не вымышленное число.
- LLM-конвейер вынесен из FastAPI event loop в worker thread, поэтому `/agents/progress/{request_id}` отвечает во время генерации.
- API принимает прогресс только текущей попытки по `updated_at`, не показывая устаревшие 100% после retry.
- Реальный runtime smoke подтвердил наблюдение промежуточной стадии во время работы Qwen.

### 6. API Core и жизненный цикл задач

Статус: базовая стойкая очередь уже была; усилено восстановление пакетов и production-контур.

- Задачи принадлежат GUID пользователя; history/status/rename/archive изолированы по `user_id`.
- PostgreSQL-очередь использует `FOR UPDATE SKIP LOCKED`, retry/backoff и восстанавливает прерванные Processing-задачи.
- Добавлен JSON checkpoint после каждого готового профиля. Retry пакета продолжает с первого незавершённого сотрудника, а не повторяет уже готовые ИОТ.
- Добавлена миграция `202608260001_AddProcessingCheckpoint`; она успешно применена к существующему volume.
- Сопоставление колонок больше не использует общий substring или позиционное угадывание. Поддерживаются явные имена колонок; неизвестная схема отклоняется.
- Новые пароли ограничены 12–128 символами; существующие хеши не мигрируются. Login также отклоняет ввод длиннее 128 символов, защищая password hasher от чрезмерной нагрузки.
- Forwarded headers применяются до rate limiting, поэтому auth-limit учитывает реальный клиентский IP за nginx.

### 7. AI pipeline и grounding

Статус: перенесён принцип evidence-first, адаптированный к рекомендациям курсов.

- Модель не является источником каталожных фактов: `course_id`, название, тип, часы, аннотация, результаты и компетенции восстанавливаются из локального каталога.
- Курс вне каталога, пройденный курс и дубль отклоняются.
- Теперь даже существующий курс отклоняется, если нет проверяемой лексической связи с явной `career_goal` и нет точного cohort evidence.
- Свободный summary модели заменяется детерминированным резюме; justification строится из явной цели, карточки каталога и конкретных чисел когорты.
- Отсутствующий бенчмарк больше не попадает в `evidence_sources` как доказательство.
- Неподтверждённые сроки, приоритеты, зависимости и многоэтапность модели не публикуются. Без календаря/пререквизитов используется один список кандидатов для экспертной проверки.
- Fallback остаётся `degraded`, не создаёт radar и явно требует эксперта.
- Для внешних моделей маскируются не только ФИО, но и его повторения, email, телефон, СНИЛС и паспортные шаблоны во всех свободных полях профиля/истории. Локальная Qwen остаётся в закрытом контуре.
- Survey evidence atoms из похожего проекта не переносились: здесь доказательствами являются профиль, карточка официального каталога и допустимый когортный срез.

### 8. Runtime-тесты модели на реальных данных

Статус: выполнен релевантный текущему продукту runtime.

- Полный путь: профиль → API Core → PostgreSQL queue → AI-driver → локальная Qwen → catalog validation → сохранённая ИОТ.
- Результат теста: `CompletedWithLimitations`, `live_progress=true`, `catalog_grounding=true`, `completed_course_excluded=true`.
- Статус с ограничениями сохранён честно; он не повышался до verified.
- Для объективной semantic accuracy всё ещё нужен экспертно размеченный набор профилей и ожидаемых рекомендаций.

### 9. Тесты и инфраструктура

Статус: усилено и проверено.

- API production Docker build/publish: 0 warnings, 0 errors.
- Frontend regression: 4/4; lint clean; Vite production build passed.
- AI tests: 10/10, включая OpenAPI, PII, grounding, fallback и model availability.
- API contract tests проходят в воспроизводимом test-image; проверяются JSON/CSV/XLSX/XLS/ZIP, неоднозначные заголовки, archive limits и auth DTO.
- ACL smoke: 12/12; platform smoke: metrics, cache, idempotency и 429 прошли.
- Базовый no-AI стек (frontend, API, AI-driver, PostgreSQL) имеет healthchecks и полностью healthy; Qwen имеет отдельный healthcheck и подключается только профилем `local-ai`.
- Отсутствие локальной модели и облачных ключей не блокирует запуск платформы. `/models/availability` возвращает `operating_mode=no-ai`, а попытка генерации отклоняется как `503 MODEL_UNAVAILABLE` до создания записи очереди.
- API и AI-driver опубликованы только на loopback (`5050` и `8000`); пользовательский frontend остаётся на `8088`.
- DataProtection keys хранятся в отдельном persistent volume; PostgreSQL volume сохраняется при recreate.
- nginx security headers и ограничение request body согласованы с API.
- Redis из похожего проекта не добавлялся: текущая очередь уже персистентна в PostgreSQL, подтверждённой необходимости второго хранилища нет.

### 10. Ограничения утверждений

Статус: сохранены честные release-границы.

- Нельзя утверждать «идеальную» semantic accuracy без gold dataset и экспертной разметки.
- Маленькая локальная Qwen может завершаться fallback-результатом; UI и экспорт обязаны показывать это ограничение.
- Выбор другой GGUF-модели не делался автоматически: ресурсный профиль и качество новой модели должны быть подтверждены отдельно.
- Vite сохраняет крупный chunk ExcelJS как performance risk, но production build и функциональность не нарушены.
- Новые роли, survey-сценарии, sentiment и неподтверждённые функции не добавлялись.
