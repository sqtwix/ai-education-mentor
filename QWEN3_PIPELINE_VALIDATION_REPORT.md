# Проверка pipeline после подключения Qwen3-1.7B Q4_K_M

Дата проверки: 26 августа 2026 года.

> Исторический отчёт эталонного Qwen-профиля. В актуальной конфигурации те же параметры называются `LOCAL_LLM_*`, а provider — `local_llm`; старые `QWEN_*` автоматически мигрируются. Результаты этой конкретной модели не распространяются автоматически на другие GGUF.

## Подключенная модель

- Файл: `models/Qwen3-1.7B-Q4_K_M.gguf`.
- Размер: 1 282 439 264 байта.
- SHA-256: `d2387ca2dbfee2ffabce7120d3770dadca0b293052bc2f0e138fdc940d9bc7b5`.
- Источник: `ggml-org/Qwen3-1.7B-GGUF`, квантование Q4_K_M.
- Runtime: `llama.cpp server`, финальный production-профиль — context 4096, 4 CPU threads, batch 512, один parallel slot. Контекст уменьшен после длительного теста: максимальный наблюдавшийся prompt был около 2517 токенов, а 8192 создавал избыточное давление памяти.
- В финальном runtime-профиле отключён prompt/idle cache llama.cpp (`--cache-ram 0`): стандартный предел кеша 8192 MiB приводил к росту памяти и рестартам на длительной серии разнородных профилей.

Локальный GGUF не входит в Git и остается в игнорируемой папке `models/`.

## Что выявлено и исправлено

1. Qwen3 по умолчанию тратила output budget на длинный ответ, из-за чего JSON трех агентов обрезался. Для локальной модели включен `/no_think`; скрытые SDK-retry отключены.
2. Архитектор и обосновывающий агент могли раздувать ответ. Контракт ограничен тремя кандидатами, а третьему агенту передаются только реально выбранные карточки каталога.
3. Длинные названия модель иногда перепечатывала с опечаткой. Каноническая связь теперь выполняется по `course_id`; имя и остальные поля всегда берутся из исходного каталога.
4. Старый matcher принимал общие слова «государственной власти» за релевантность и рекомендовал курс про социальные сети для проектного управления. Ранжирование и финальная проверка переведены на консервативные значимые корни с удалением общих контекстных слов.
5. Грубое обрезание корня ошибочно сближало «организмов» и «организация». Добавлена консервативная нормализация окончаний и регрессия по всему каталогу.
6. До финального агента теперь выполняется серверная фильтрация по переданным кандидатам, цели и подтвержденной когорте. Отклонения агрегируются в одну понятную причину, а не выводятся длинным списком.
7. Четыре параллельных slot оказались нестабильны. Установлен обязательный `QWEN_PARALLEL=1`; многопользовательские задания сериализует стойкая очередь API.
8. После restart AI-driver мог начать batch, пока Qwen еще загружалась, и быстро обработать остаток через fallback. Добавлен readiness wait до 180 секунд перед каждым локальным профилем.
9. При транспортном обрыве из-за рестарта модели повторяется один раз только незавершенный агент. Невалидный JSON и смысловые нарушения не повторяются и не маскируются.
10. API и UI теперь показывают фактический файл `Qwen3-1.7B-Q4_K_M.gguf`, а не общий alias `local-model` и не старую подпись Qwen 2.5.

## Проверка содержания

### Точная цель: проектное управление

Итог после исправлений: `generation_mode=llm`, `quality_status=verified`.

Приняты три кандидата:

- `EK_004` — «Проектное управление в органах государственной власти»;
- `PPK_085` — «Руководство проектами в органах исполнительной власти»;
- `PPK_086` — «Инструменты управления для реализации национальных целей».

Третий кандидат проверен по исходной карточке: в ней прямо указаны проектный подход, паспорт проекта, управление рисками, контроль проектов, Agile, Scrum и Kanban. Нерелевантный курс про социальные сети, который проходил старый matcher, после исправления отклоняется.

### Широкая цель: управление проектами и командой

Получены релевантные кандидаты по проектному управлению, современным проектным методологиям и управлению командной ресурсностью. В параллельном диагностическом запуске результат был честно помечен `degraded`, потому что два прямых запроса обошли штатную очередь и конкурировали за модель; production-профиль после этого зафиксирован как single-slot.

### Цель вне каталога: ксенобиология

Итог: ноль курсов. Сервер отклонил все предложения модели как не имеющие проверяемой связи. Регрессионный тест дополнительно проверяет отсутствие совпадения этой цели со всеми 159 карточками каталога.

## Runtime-проверки

| Проверка | Результат |
|---|---|
| Прямой JSON Qwen3 | Валидный JSON, около 54 токенов/с на коротком запросе |
| Финальный одиночный E2E | `Completed`; повторно пройден на context 4096 и cache-free runtime |
| 3 пользователя через очередь | 71 / 152 / 219 с, изоляция задач подтверждена |
| Restart/checkpoint, 5 профилей | 393 с, attempt 2, продолжение после checkpoint 2, checkpoint очищен |
| Финальный максимальный batch, 15 профилей | 1488 с, `CompletedWithLimitations`, attempt 2, продолжение после checkpoint 2, все 15 результатов сохранены |
| Каталожная привязка | Все опубликованные курсы входят в официальный каталог |
| Пройденные курсы | Исключены во всех smoke-тестах |
| Матрица компетенций | Не публикуется без подтвержденных измерений |
| Unit/contract AI-driver | 21 тест пройден |

Промежуточные прогоны выявили накопительный рост RAM из-за стандартного prompt cache llama.cpp: модель перезапускалась, а transport-recovery корректно повторял только незавершённого агента. В окончательном профиле cache отключён, context снижен до 4096 и server image закреплён по digest. Повторный 15-профильный прогон после этих изменений завершился без самостоятельных рестартов Qwen и без OOM. `CompletedWithLimitations` ожидаем для синтетических тестовых ведомств, не имеющих подтверждённой когорты: pipeline не подставляет статистику из другой группы.

## Ресурсы и ограничения

- После загрузки и контрольного E2E финальный cache-free профиль использовал около 3.14 GiB RAM контейнера при лимите Docker 7.74 GiB.
- OOM в подтвержденных проверках не зафиксирован.
- Qwen3-1.7B заметно медленнее прежней Qwen2.5-0.5B, но лучше следует предметной задаче после адаптации prompt/grounding.
- Semantic accuracy нельзя называть идеальной без экспертно размеченного gold dataset по траекториям. Сервер гарантирует каталожную и фактическую привязку, но педагогическую оптимальность набора курсов должен оценивать предметный эксперт.

## Итог

Qwen3 подключена и используется в исходной задаче проекта — построении индивидуальных образовательных траекторий. Назначение продукта не менялось. Pipeline устойчив к невалидному JSON, нерелевантным и выдуманным программам, опечаткам длинных названий, рестарту AI-driver и временной недоступности модели. Для текущих ресурсов production-профиль должен оставаться последовательным (`QWEN_PARALLEL=1`).
